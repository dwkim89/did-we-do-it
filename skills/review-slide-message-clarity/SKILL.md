# Review Slide Message Clarity

Make the deck easy to follow while it is being presented. Review the argument
across slides, not only the wording or visual layout within one slide.

Use this skill after a complete draft has been rendered and before final
handoff. Use `simplify-slide-language` separately for sentence-level wording and
the deck-production skill for compilation and visual checks.

## Workflow

1. Write the audience's required takeaway and meeting decision in one sentence
   each. If the source does not support either, state the unresolved question
   instead of inventing an answer.
2. Make a compact message map for every main slide:
   - what the audience knows before the slide;
   - the one question or claim on the slide;
   - the evidence shown or still required;
   - the supported result or expected use;
   - why the next slide follows.
3. Check the whole-deck path. A useful technical sequence is:
   - team-wide status;
   - observed problem and current evidence limit;
   - validation that makes later comparisons trustworthy;
   - comparison rule or method;
   - evidence or planned checks in dependency order;
   - implication, next action, and decision.
   Reorder slides when the audience must understand a later premise earlier.
4. Apply the evidence-state test to every slide:
   - completed evidence uses `supports`, `challenges`, or `does not resolve`;
   - missing evidence uses `question to answer`, `what this will tell us`, or
     another prospective label;
   - never say `answered`, `established`, or `done` when the named evidence is a
     placeholder.
5. Apply the necessity test. Remove statements that merely repeat the title,
   table, meeting purpose, or an obvious transition. Keep context only when the
   audience needs it to interpret the next result.
6. Apply the transition test to each neighboring pair. The second slide must
   answer a question raised by the first, establish a needed premise, or state
   the next decision dependency. Add a short bridge only when reordering and a
   clear title cannot make the connection obvious.
7. Audit the conclusion backward. Every conclusion must trace to displayed
   evidence or be labeled as a planned decision. Keep association, sensitivity,
   and causation distinct.
8. Read the rendered main deck at speaking pace. A collaborator should be able
   to state, without project history: the problem, what was checked, what was
   learned, what remains open, and what decision comes next.
9. Revise the smallest set of slides, recompile, and repeat the message and
   visual review because changed text or order can alter layout.

## Completion criteria

- Each main slide has one clear job in the argument.
- The reason for every check is stated before or with the check.
- Evidence status and conclusion strength agree.
- No neighboring slides require an unstated logical jump.
- The conclusion is a compact consequence of the displayed evidence.
- The visual hierarchy makes the main message easier, not harder, to find.
